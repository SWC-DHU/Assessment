| 审查项 | 现状与实施选择 |
| --- | --- |
| 领域本体 | 本体与词表均为 3.0.0，六个核心类与辅助物料状态、整线范围能表达当前需求。OWL 提供关系端点，词表提供工序和能力别名、参数及单位。任务、来源和审核属于交换契约。保留现有 RDF 及其版本，保持 JSON `Capability` 到 OWL `CapabilityRequirement` 的映射。 |
| 正式模型 | 2.1.0 包含产品、工序、物料、状态、能力、约束、关系、建模意图、工艺图、来源、证据、问题和校验，另有运行、摘要、版本与抽取覆盖元数据。优先使用已有事实引用。 |
| 候选到实例 | `parser.py` 和来源适配器生成坐标片段，`semantic_execution.py` 先调用表格及明确文本规则，再对剩余片段执行有界候选抽取和恢复。`pipeline.Builder` 逐条校验候选、核对引文、查词表、实例化、验证并回填引用。 |
| 建模意图 | `modeling_intents` 保存 Objective，缺少明确任务作用范围、产物和目标产品引用。用任务组织已有目标及整线约束，证据不足时保留空值。 |
| 工序需求 | Operation 已有编号、标准词、能力、约束、物料、状态、前驱、信息流、原文设备要求和来源。模板可解析部分引用，下游缺少自包含交换结构。 |
| 工艺拓扑 | 图保留主线、旁路、汇合、条件、可选和显式返工。普通时序及业务依赖保留间接语义。图由后端投影；原文件中的未说明流向保留为问题。 |
| 校验 | 已检查引文、OWL 端点、能力映射、一些引用、数值与单位冲突、工艺环及返工上限。需补充任务引用、返工条件和交接完整性判定。 |
| 保存与导出 | 会话运行、显式投影及人工审核生成语义版本，保存至 SQLite；模板用兼容投影。工作台已有历史、原文定位、图和语义 JSON 浏览。 |
| 前端契约 | 自定义抽取 Schema 用于旧版运行，正式语义运行使用后端候选契约。当前界面缺少三种契约的清晰浏览入口和下游预览。 |
| 原始案例 | 工作簿 Sheet1 的 A:H 列含 16 道工序、3 道旁路、两处汇合及两条信息产出。8 个电芯及 120 s/模组来自独立自然语言。保持原始输入和 Gold。 |
