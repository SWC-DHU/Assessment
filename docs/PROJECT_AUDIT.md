# Assessment 开发前审查

## P0 回归基线

- Assessment 不含 Git 元数据，无法读取分支或未提交差异。
- 后端 Python 3.12 虚拟环境下 `.venv/bin/pytest -q` 通过 19 项测试。
- 前端 `npm run build` 通过，存在构建包大小提示。
- 对现有 SQLite 只读检查发现 1 个会话、4 条消息、1 份上传文件、1 套智能体和 2 套模板。历史错误包含 HTTP 403。

## 架构和问题

FastAPI 路由编排 SQLAlchemy ORM、SQLite 及本地 uploads。解析器输出带坐标的文本与文件预览。OpenAI 兼容客户端负责 Prompt、抽取、JSON 格式回退及连通性测试。会话保存消息、最后一次 JSON 和 Debug。Jinja2 和表格映射共用渲染与导出层。前端是 Vite、React 18、TypeScript、Ant Design 6、Tailwind、Lucide，组件以 App 的 React 状态协调，无独立客户端路由或状态库。

已有 JSON 直接进入模板，缺少独立的语义规则和逐条证据验证。历史 Excel 引用可以只是行范围。真实模组表有 16 道工序、三道旁路工序及显式的汇合与工艺条件；没有核心设备型号或工时列。模板里的空值无法据此补全。旧拓扑及 Debug 也缺少统一的语义状态。403 的诊断未区分模型授权与服务策略。停止运行依赖客户端中止请求，宽屏分栏存在固定最小宽度。

## 实施顺序及兼容性

1. P1 建立静态 Turtle 本体、YAML 词表、Pydantic Schema 和独立验证。
2. P2 复用原 Provider 和文档解析，增加结构化行抽取、逐字核验、语义版本、模板投影及受控修订。通过新表添加持久化，保留旧会话 JSON、模板定义和上传文件。
3. P3 保留素材、对话、智能体配置和模板编辑入口，完善不同屏幕布局、可交互结果、单元格诊断与分阶段追踪。
4. P4 使用隔离数据库和真实工作簿执行回归，建立人工对照事实及可重复实验命令。外部真实 Provider 和费用相关验证按实际可用条件报告。

旧模板字段通过兼容投影保留。旧历史 JSON 在用户显式转换前沿用原格式。直接依赖旧 JSON 编辑或自定义抽取 Schema 的调用需关注语义版本与兼容字段的区别。
