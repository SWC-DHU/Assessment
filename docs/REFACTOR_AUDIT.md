# 第二次重构的现状审查

Assessment 的当前 Git 分支是 `main`。开始时仅有未跟踪的 `test case/`，其中包含用户的原始 XLSX 和自然语言需求，两份文件均纳入只读回归。基线为后端 33 项测试通过、TypeScript/Vite 构建通过。原有 README、API、领域契约、实验脚本与历史记录一起审阅。

## 已确认的实现和问题

- FastAPI 会话路由解析文件引用，经 `source_inputs` 提供带工作表行列、页码或字符位置的来源。已有 `semantic_execution.execute` 先识别表格行，再使用 OpenAI 兼容调用获取候选。Builder 实例化并映射词表，Python 校验后保存版本、会话与模板投影。React 从会话 API 获取版本和 Debug。
- 旧本体在 `backend/domain_semantics/ontology`，由 RDFLib 读取作为目录。Schema、OWL 端点与 Python 校验分别手工维护。旧拓扑在 React 上由通用关系列表推导，汇合和前驱可形成视觉重边，后端没有标准图快照。
- 当时由程序直接调用文件解析、抽取、规则映射和验证函数。Provider 请求只有消息与 JSON 输出选项，没有 function-calling 工具注册或可查询的工具执行轨迹。Prompt 要求的语义判断依靠候选文本，能力消歧是单独的模型请求。
- SQLite 中实际的混合输入运行使用 `deepseek-flash`。两次请求均以 `length` 结束，每次耗尽 16,383 个输出 Token，共 32,766 个输出 Token。旧流程仍将表格序列化为全部单元格，修复再加入原始截断输出并要求重写全量 JSON。文件事实被保留，但会话显示成功，缺失抽取范围不够明确。
- 原有 v1 Schema 保存产品、工序、物料、能力、约束、通用关系与内嵌证据。证据定位和事实验证的界面用语接近，人工确认缺少专门的数据与版本入口。

## 案例及现有实验

工作簿 Sheet1 已与人工转录的 Gold 核对。它包含 16 道工序、3 道旁路，05 自 04 和 Z1 汇合，08 自 07、Z2 和 Z3 汇合。检测输出区分合格与不合格，G 列给出依赖，但原表没有明确的不合格后续路线或返工边。各单元格的能力、物料状态和质量要求为事实来源。自然语言另给出标准模组的 8 个方形电芯及结构连接件、设计下线节拍 ≤120 s/模组，以及后续设备匹配、模型关联和仿真验证意图。已有三步合成 Gold 含 Z1 与主线依赖汇合、物料、能力和量化节拍；单工序合成集用于真实 Provider 烟测。历史 A/B/C 标识和记录继续保留。

## 设计变更

更新一份可查询的 OWL/RDF 词汇及端点契约，保留 v1 目录。扩充强类型模型、事实状态、工艺图及人工审核。将结构化表格优先处理，按来源范围调度有界候选抽取与局部恢复，用显式部分完成状态和实际工具轨迹串联 API 与工作台。计划变更集中在领域包、会话与语义 API、Provider 编排、工作台和测试目录。
